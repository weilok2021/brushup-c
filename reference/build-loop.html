The Build Loop

Compile flags, the header split, a minimal Makefile, and how to read what the tools say back. Lookup only, nothing here is to be memorised. Paired with Lesson 1.

The loop

Edit → make → ./prog → make check → read the report → fix. A warning is a failed build. A sanitizer or valgrind report is a failed run, even if the output looked right. Two checkers because they cover different bugs: the sanitizer catches out-of-bounds and use-after-free the instant they happen; valgrind catches leaks at exit.

gcc -std=gnu11 -Wall -Wextra -g -fsanitize=address,undefined -o prog main.c module.c   # ./prog
gcc -std=gnu11 -Wall -Wextra -g -o prog-plain main.c module.c                           # valgrind --leak-check=full ./prog-plain
FlagPurpose
-std=gnu11C11 plus POSIX library (strdup, getline). Plain c11 hides those.
-Wall -WextraThe bug-catching warnings. gcc docs
-gDebug info: reports and gdb show file:line.
-fsanitize=address,undefinedAddressSanitizer (out-of-bounds, use-after-free, double free) + UndefinedBehaviorSanitizer (overflow, bad shifts, null deref). gcc docs. Its built-in leak check is unreliable at -O0: stale pointer copies in dead stack frames make a leaked block look reachable. Use valgrind for leaks.
-O0 (default)No optimisation while learning: line numbers stay honest.

The header split

module.h — the promise

#ifndef MODULE_H
#define MODULE_H

#include <stddef.h>

/* One-line contract per function. */
int module_fn(const int *a, size_t n);

#endif

module.c — the implementation

#include "module.h"   /* first line: check
                         definitions against
                         your own prototypes */

int module_fn(const int *a, size_t n) {
    /* ... */
}

main.c — the client

#include <stdio.h>
#include <stdlib.h>
#include "module.h"   /* never module.c */

Guard name = file name in capitals, no leading underscore. Prototypes and shared struct declarations go in the header; everything else stays in the .c. Source: Beej ch. 17.

Minimal Makefile

Makefile  ·  ⇥ = one real tab character

CC     = gcc
CFLAGS = -std=gnu11 -Wall -Wextra -g
SAN    = -fsanitize=address,undefined
SRC    = main.c module.c

prog: $(SRC) module.h
⇥$(CC) $(CFLAGS) $(SAN) -o prog $(SRC)

# valgrind cannot run a sanitized binary, so it gets a plain one
prog-plain: $(SRC) module.h
⇥$(CC) $(CFLAGS) -o prog-plain $(SRC)

.PHONY: check clean
check: prog-plain
⇥valgrind --leak-check=full --error-exitcode=1 ./prog-plain
clean:
⇥rm -f prog prog-plain
PieceMeaning
target: prerequisitesRebuild target when any prerequisite is newer. Put headers in the list.
recipe lineMust start with a tab. Spaces → *** missing separator. GNU make §4.2
.PHONYThese targets are commands, not files.
make / make check / make cleanBuild the sanitized binary / build a plain one and run it under valgrind / remove both.
make -n / make -BShow what would run / force a full rebuild.

Reading a sanitizer or valgrind report

Look at three things: the kind on the ERROR line, frame #0 of the first stack (file:line of the bad access), and the region sentence or the allocation stack that says which block. Valgrind's leak report has the same three: “definitely lost”, the byte count, and the by … main (main.c:6) line under the malloc.

HeadingMeaningUsual cause
heap-buffer-overflowRead/write past a malloc'd block.<= for <; off-by-one on size; forgot the NUL byte in a string.
stack-buffer-overflowSame, for a local array.Index equal to the array length.
heap-use-after-freeTouched a block after free.Freed a node, then read node->next.
attempting double-freeSame pointer freed twice.Two owners both freeing; loop frees then cleanup frees again.
definitely lost (valgrind, via make check)At exit: a block never freed that nothing points to, with the allocating stack. “All heap blocks were freed -- no leaks are possible” is the clean result.Missing free; early return skipping cleanup; pointer overwritten before the free.
still reachable (valgrind)Never freed, but a pointer to it still exists at exit.Usually a global or a static kept alive to the end. Free it anyway in this course.
runtime error: signed integer overflow (UBSan)Arithmetic left the range of the type.int where long or size_t was needed.
SEGV on unknown address 0x000…Dereferenced NULL or garbage.Unchecked malloc; uninitialised pointer; wrong level of *.
