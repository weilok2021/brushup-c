Recursive Sorts

Merge sort and quicksort over a closed range [lo, hi], the promise each one keeps, and the size_t rules that keep the recursion finite. Paired with Lesson 8.

Interface

sort.h

void swap_ints(int* a, int* b);              /* lesson 5 */
int  is_sorted(const int* a, size_t n);      /* lesson 5 */
void merge_sort(int* a, size_t lo, size_t hi);   /* a[lo..hi], stable; merge frees its own copies */
void quick_sort(int* a, size_t lo, size_t hi);   /* a[lo..hi], in place */

Closed range: a whole array of n items is (a, 0, n - 1), and n must be at least 1 or n - 1 wraps. merge and partition are static in sort.c.

The shape

Promise. After sort(a, lo, hi), a[lo..hi] is ascending. Base case lo >= hi. Shrink into two ranges that leave something out. Trust the promise on each. Do the one piece of work the halves cannot.
stack (one frame per call)                  heap
main               a ────────────────────▶  [ n ints ]   owner: main
merge_sort         a, lo=0, hi=7
merge_sort         a, lo=0, hi=3
merge_sort         a, lo=0, hi=1
merge_sort         a, lo=0, hi=0            base case: returns
merge (later)      left, right ──────────▶  two small blocks, freed before return

Arguments are copies. lo and hi are private to each frame; every copy of a is the same address, so every frame writes into the same block.

Merge sort

Work after the calls. merge is lesson 7's: copy the runs out, merge back into a[lo..hi], free the copies. Ties take the left run (stable).

void merge_sort(int* a, size_t lo, size_t hi) {
    if (lo >= hi) return;                          /* 0 or 1 item */
    size_t mid = lo + (hi - lo) / 2;
    merge_sort(a, lo, mid);                        /* trust */
    merge_sort(a, mid + 1, hi);                    /* trust: mid + 1, not mid */
    merge(a, lo, mid, hi);                         /* work */
}
FactValue
Costabout n log n, any input: log n levels, each touching all n items once
Mergesn - 1; each allocates and frees its two run copies
Stack depthabout log n frames
Stableyes, if ties take the left run

Quicksort

Work before the calls. partition is lesson 7's: returns p with a[lo..p-1] <= a[p] <= a[p+1..hi], and a[p] never moves again.

void quick_sort(int* a, size_t lo, size_t hi) {
    if (lo >= hi) return;                          /* 0 or 1 item, or lo > hi */
    size_t p = partition(a, lo, hi);               /* work */
    if (p > lo) quick_sort(a, lo, p - 1);          /* trust; guard: p - 1 wraps at 0 */
    quick_sort(a, p + 1, hi);                      /* trust; p + 1 <= hi + 1 is safe */
}
FactValue
Costabout n log n typical; n² when every pivot lands at an end (sorted input, leftmost pivot)
Extra spacenone on the heap; the stack only
Stack depthabout log n typical, n worst case
Stableno
Equal keysboth scans stop on them (lesson 7)

Closed-range recursion rules

Never writeWrite insteadBecause
merge_sort(a, mid, hi)(a, mid + 1, hi)mid is the last index of the left half. Two items have mid == lo, so the right call is the same range: stack overflow.
quick_sort(a, lo, p - 1) unguardedif (p > lo) ...p can be 0. 0 - 1 on size_t is SIZE_MAX; the read lands 4 bytes before the block.
quick_sort(a, lo, p)(a, lo, p - 1) and (a, p + 1, hi)The pivot is placed. Leaving it out is what makes both sides shorter.
merge_sort(a, 0, n - 1) with n possibly 0check n >= 1 at the call siten - 1 wraps when n is 0. No wrapper here, so the caller checks.
if (lo == hi)if (lo >= hi)Quicksort's right call can produce lo == hi + 1. Catch it.
