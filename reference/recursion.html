Recursion

Base case, shrink, trust: the two rules that keep a recursion finite, the four shapes over a half-open range, and what the reports look like when a rule breaks. Paired with Lesson 6.

Two rules and one act of trust

RuleMeaningTest before running
Base caseSome range is answered without a call.State it in one sentence: “the empty range sums to 0”.
ShrinkEvery other call receives a strictly smaller range.Point at the argument that is smaller. [lo + 1, hi), [lo, mid), [mid + 1, hi).
TrustAssume the call on the smaller range is correct; write one step that uses it.Do not trace the inner call while writing the outer line.

long sum_range(const int* a, size_t lo, size_t hi) {          /* shrink by one */
    if (lo == hi) return 0;
    return a[lo] + sum_range(a, lo + 1, hi);
}
void print_backwards(const int* a, size_t lo, size_t hi) {    /* work after the call */
    if (lo == hi) return;
    print_backwards(a, lo + 1, hi);
    printf(" %d", a[lo]);
}
int max_range(const int* a, size_t lo, size_t hi) {           /* halve, use both */
    if (hi - lo == 1) return a[lo];
    size_t mid = lo + (hi - lo) / 2;
    int l = max_range(a, lo, mid), r = max_range(a, mid, hi);
    return l > r ? l : r;
}
const int* search_range(const int* a, size_t lo, size_t hi, int t) { /* halve, keep one */
    if (lo == hi) return NULL;
    size_t mid = lo + (hi - lo) / 2;
    if (a[mid] == t) return &a[mid];
    return t < a[mid] ? search_range(a, lo, mid, t) : search_range(a, mid + 1, hi, t);
}

The promise: proving the answer

The two rules prove that a recursion stops. They say nothing about whether its answer is right. For that, write one sentence that is true on every call (the invariant) above the function, then run three checks. From lesson 6b.

Promise for search_range. a[0..n) is sorted, and if target is anywhere in a[0..n), then it is in a[lo..hi).
CheckQuestionFor search_range
1. First callDoes the caller keep the promise?[0, n) holds everything. Kept.
2. Every callDoes each recursive call keep it?target < a[mid]: sorted, so nothing at or after mid matches; [lo, mid). target > a[mid]: nothing at or before mid; [mid + 1, hi).
3. Every returnGiven the promise, is each return right?lo == hi: the target is in an empty range, so nowhere; NULL. a[mid] == target: &a[mid].

Both halves are strictly smaller because of one arithmetic fact. With k = hi - lo >= 1 and mid = lo + k / 2: k / 2 >= 0 gives lo <= mid, and k / 2 < k gives mid < hi. So a[mid] is in bounds, [lo, mid) has k / 2 elements and [mid + 1, hi) has k - k / 2 - 1. Write it in the code as assert(lo <= mid && mid < hi); if in doubt.

Pick one range convention, write it in the header, and make every line obey it. A half-open header over a closed body (lo > hi, mid - 1) is the mixing that broke the lesson 6 draft.

Frames

Every call is a new frame with its own copies of every parameter. Pointer copies share the block; index copies are private. Work placed after the call runs when the deeper frame returns, so the deepest frame acts first.

(gdb) break sum_range if lo == 3      stop when a condition holds
(gdb) run
(gdb) backtrace                        one line per live frame, #0 newest
(gdb) up                               move to the caller's frame
(gdb) info frame                       addresses of the current frame
(gdb) quit

Depth is the cost: a chain of one frame per element overflows the 8 MB stack at about a hundred thousand elements; a halving tree needs about 20 frames for a million.
