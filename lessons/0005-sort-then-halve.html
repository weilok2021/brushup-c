Sort, Then Halve

Insertion sort keeps a sorted prefix growing by one, and binary search keeps a shrinking half-open range. Both run on a plain int array you own.

About 35 minutes Where: WSL, exercises/05-sort-search/ Mission · Cheat sheet · Lesson 4
Your win today. Write a swap through two pointers, an insertion sort built on that swap, a binary search that cannot underflow, and a test that checks the postcondition instead of eyeballing output.

A swap needs two addresses

Two ints live at two addresses:

address:   0x100   0x104
value:        9       4

A function that receives the values 9 and 4 receives copies. It can swap its copies all day and the caller's memory stays 9 4. A function that receives the addresses 0x100 and 0x104 can write through them:

void swap_ints(int* a, int* b) {
    int tmp = *a;      /* read 9 from 0x100 */
    *a = *b;           /* write 4 into 0x100 */
    *b = tmp;          /* write 9 into 0x104 */
}

swap_ints(&x[1], &x[0]);   /* caller passes addresses */
Beej, section 5.4: “The function can dereference its copy of the pointer to get back to the original variable!” Passing Pointers as Arguments.

This is the same rule as lesson 4's char** slot, one level down: to change the caller's thing, receive its address.

Insertion sort: the left part is always sorted

Start with eight numbers. Treat the first one as a sorted run of length one. Then take each next number and walk it left, swapping with its neighbour, until the neighbour on its left is no bigger:

i=1   31 | 4  15  9  26  5  35  8      4 < 31, swap
      4  31 | 15  9  26  5  35  8      run is now a[0..1]
i=2   4  31 | 15 ...                  15 < 31, swap; 15 > 4, stop
      4  15  31 | 9 ...
i=3   4  15  31 | 9 ...               9 < 31 swap, 9 < 15 swap, 9 > 4 stop
      4  9  15  31 | 26  5  35  8
            ^ everything left of the bar is sorted, always

The vertical bar is the invariant: before the loop handles index i, the range a[0..i) is sorted. Each pass extends it by one. When i reaches n, the whole array is sorted. Sedgewick and Wayne describe the same move as inserting each card “into its proper place among those already considered (keeping them sorted)”*.

In C, with the swap from above:

void insertion_sort(int* a, size_t n) {
    for (size_t i = 1; i < n; i++) {
        for (size_t j = i; j > 0 && a[j] < a[j - 1]; j--) {
            swap_ints(&a[j], &a[j - 1]);
        }
    }
}

Read the inner condition carefully. j > 0 comes first, so a[j - 1] is only evaluated when j - 1 is a valid index. Writing j >= 0 with a size_t is always true, because an unsigned value cannot go below zero. gcc warns about it, and the run reads before the block.

Cost: on a random array, about n²/4 compares and n²/4 swaps. On an already sorted array, n - 1 compares and zero swaps*. That makes insertion sort the right tool for small or nearly sorted inputs, and the wrong tool for a million random ints. Lesson 8 fixes that with recursion.

Binary search: keep the candidates in a half-open range

The array is sorted: 4 5 8 9 15 26 31 35. Search for 26. Keep two indices, lo and hi, such that every candidate lives in [lo, hi): from lo inclusive up to hi exclusive.

lo=0 hi=8   mid=4  a[4]=15  15 < 26   lo = 5       candidates [5, 8)
lo=5 hi=8   mid=6  a[6]=31  31 > 26   hi = 6       candidates [5, 6)
lo=5 hi=6   mid=5  a[5]=26  found     return &a[5]

Each step throws away half the candidates. Eight becomes four, then two, then one. For n elements that is about log₂ n steps: 20 steps for a million*. The precondition is that the array is sorted; on an unsorted array the result is meaningless, not an error.

const int* search_sorted(const int* a, size_t n, int target) {
    size_t lo = 0;
    size_t hi = n;                      /* candidates in [lo, hi) */
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2;
        if (a[mid] == target) {
            return &a[mid];
        }
        if (a[mid] < target) {
            lo = mid + 1;               /* mid is too small, drop it */
        } else {
            hi = mid;                   /* mid is too big, it becomes the bound */
        }
    }
    return NULL;
}

Why half-open, and why it matters in C. Textbooks often write the closed form, hi = n - 1, while (lo <= hi), hi = mid - 1. With signed ints it works. With size_t, the moment mid is 0 and the target is smaller than a[0], hi = mid - 1 wraps to the largest possible value, the loop keeps going, and the next a[mid] reads outside the block. The half-open form never subtracts one from an index, so it cannot wrap. Sedgewick and Wayne state the invariant as “the key is in a[lo..hi] if it is in the array”*; the half-open version keeps the same idea with an exclusive upper bound.

The midpoint is written lo + (hi - lo) / 2 rather than (lo + hi) / 2. The two are equal for arrays this size; the first form cannot overflow when lo + hi exceeds the type's range, so it is the habit to keep.

The function returns a pointer to the element, or NULL, the same shape as lesson 4's words_find. The caller turns the pointer into an index with hit - a and prints it with %td, as in lesson 2.

A test is a checked postcondition

Looking at after: 4 5 8 9 15 26 31 35 and nodding is not a test. A test asks the program to check the claim itself. For a sort, the claim is “no element is smaller than the one before it”:

int is_sorted(const int* a, size_t n) {
    for (size_t i = 1; i < n; i++) {
        if (a[i] < a[i - 1]) {
            return 0;
        }
    }
    return 1;
}

CS107 expects every program you hand in to come with this kind of self-check*. From this lesson on, each exercise's main prints at least one line that a function computed, not one that you read off the screen.

The interface

sort.h

#pragma once

#include <stddef.h>

/* Exchange the two ints at a and b. */
void swap_ints(int* a, int* b);

/* Sort the n ints at a into ascending order, in place. */
void insertion_sort(int* a, size_t n);

/* Return 1 if the n ints at a are in ascending order, else 0. */
int is_sorted(const int* a, size_t n);

/* Binary search the n sorted ints at a for target.
   Returns a borrowed pointer to a matching element, or NULL if absent. */
const int* search_sorted(const int* a, size_t n, int target);

Two functions take int* because they write. Two take const int* because they only read. That is the whole const story for this lesson.

Reading the wrap-around failure

The closed-form search for 2 ends with mid = 0, a[0] = 4 > 2, and hi = mid - 1. That subtraction wraps hi to the largest size_t. The loop continues, computes a huge mid, and the address arithmetic wraps again, landing just before the block:

ERROR: AddressSanitizer: heap-buffer-overflow
READ of size 4 ...
    #0 ... in search_sorted sort.c:...
    #1 ... in main main.c:...
0x... is located 4 bytes before 32-byte region
allocated by thread T0 here:
    #0 ... in malloc
    #1 ... in main main.c:...

Eight ints × four bytes explain the 32-byte region. “4 bytes before” means index −1: an unsigned index has wrapped. When you see a read just before a block in code that uses size_t, look for a - 1 on an index that can be zero.

Read next

Everything here is C. Read in this order; the first two items are short source files, not chapters.

  1. Insertion sort in C. Mark Allen Weiss, Data Structures and Algorithm Analysis in C, 2nd ed., sort.c, the InsertionSort function at the top (the author publishes the book's source files free). Twelve lines. It uses the shift form: hold A[P] in Tmp, slide larger elements right, drop Tmp into the gap. Compare it with your exchange form and count the moves per step. Notice j > 0 && A[j - 1] > Tmp: the same order of tests you wrote, and for the same reason.

  2. Binary search in C. Weiss, fig2_9.c, BinarySearch. This is the closed form: High = N - 1, while (Low <= High), High = Mid - 1. It is correct because Low, Mid and High are signed int. Ask yourself, line by line, what would break if you changed those three to size_t. That is the wrap-around from step 6 of the exercise.

  3. Passing pointers. Beej, 5.4 Passing Pointers as Arguments. Two pages. This is the whole story behind swap_ints.

  4. If you prefer to watch first. CS50 Shorts, Doug Lloyd: Insertion Sort and Binary Search. About ten minutes each, from Harvard's C-based introductory course. They step through arrays by hand, no code.
