One Owner, One Free

A local pointer on the stack, a resizable block on the heap, and one rule that prevents leaks, use-after-free, and double-free.

About 25 minutes Where: WSL, exercises/03-owned-ints/ Mission · Cheat sheet · Lesson 2

The pointer and the block live in different places

Start with a concrete program state. Suppose main has just run int* values = calloc(4, sizeof *values);. On this machine it looks like this:

main's stack frame                    heap
+--------------------+               +-------------------+
| count:  4          |               | 0 | 0 | 0 | 0     |
| values: 0x6030 ----+-------------->| four int elements |
+--------------------+               +-------------------+

values is a local pointer variable. It disappears automatically when main returns. The four integers form a separate heap block. That block remains allocated until somebody passes its address to free. Losing the local pointer does not free the block.

StorageLifetimeWho ends it
Local variablesUntil their block or function returnsThe language, automatically
Global and static variablesThe whole programThe process ending
A block from malloc or callocFrom successful allocation until free or successful reallocYour program

The C standard names these storage durations; programmers usually call the first region the stack and the last the heap. The distinction that matters is automatic versus manual lifetime.

Give every heap block one owner. Ownership is a rule in your program, not a property stored in a pointer. The owner is responsible for exactly one eventual free. Other pointers may borrow the block, but borrowers do not free it and do not use it after the owner frees or resizes it.

int* values = ints_new(4);    /* values owns the returned block */
int* first = values;          /* first borrows; it does not own */

printf("%d\n", *first);       /* allowed while the block lives */
free(values);                 /* owner's one free */
/* values and first are now dangling; dereference neither */

free releases the block. It does not erase every pointer that contains the old address. Those stale pointers are dangling pointers. Assigning the owner NULL after free can prevent an accidental second free through that variable, but it cannot repair aliases such as first.

Four allocation operations, one lifecycle

OperationWhat it doesResult
malloc(bytes)Allocates uninitialised bytes. Reading them before writing a value is an error.New owning pointer, or NULL.
calloc(count, size)Allocates count * size bytes and clears them to zero.New owning pointer, or NULL.
realloc(p, bytes)Changes a block's size. It may move the block. Existing contents survive up to the smaller of the old and new sizes; added bytes are uninitialised.On success, the only pointer to use for the resized block. On failure, NULL while p's block still lives.
free(p)Ends the block's lifetime. free(NULL) does nothing.No value; every pointer into that block becomes dangling.

Beej's summary is direct: memory from malloc is not initialised, and using a region after free is undefined behavior*. All allocation results must be checked before dereferencing them.

Never overwrite the owner with realloc's result before checking it. This tempting line loses the old block when the resize fails:

values = realloc(values, new_count * sizeof *values);  /* unsafe */
if (values == NULL) {
    /* the old block still exists, but its address was overwritten: leak */
}

Keep the original owner until success is known:

int* grown = realloc(values, new_count * sizeof *values);
if (grown == NULL) {
    free(values);                /* old block still belongs to us */
    return 1;
}
values = grown;                  /* ownership continues here */

After success, use only grown (or values after the assignment). The pointer passed to realloc and every old alias must no longer be used, even when the returned address happens to look unchanged*.

The module states its ownership contract

Function comments must say who owns a returned heap block and what happens on failure. Use this header for the exercise. It uses your preferred pointer spacing; each declaration names one variable.

ints.h

#pragma once

#include <stddef.h>

/* Allocate n zeroed ints. n must be at least 1.
   Returns an owned heap block, or NULL on failure. */
int* ints_new(size_t n);

/* Resize values to hold n ints. n must be at least 1.
   On success, returns the owning pointer and the input pointer must not be used.
   On failure, returns NULL and the caller still owns values. */
int* ints_resize(int* values, size_t n);

/* Return the sum of the n ints at values. Borrows values; does not free it. */
int ints_sum(const int* values, size_t n);

The first two functions return ownership. The last function only borrows. A type such as int* cannot encode that difference, so the contract must. ints_resize may return realloc directly because its parameter is only a copy of the caller's pointer; the caller keeps its owner unchanged until it checks the returned pointer.

Reading the three reports

A use-after-free report contains three moments in the block's life:

ERROR: AddressSanitizer: heap-use-after-free ...
READ of size 4 ...
    #0 ... in main main.c:...
...
freed by thread T0 here:
    #0 ... in free
    #1 ... in main main.c:...
...
previously allocated by thread T0 here:
    #0 ... in realloc
    #1 ... in ints_resize ints.c:...

Read it as a timeline: the last stack created the current block, the middle stack ended its lifetime, and the first stack tried to read it afterward. READ of size 4 is one int.

A double-free report moves the first question from “where was it read?” to “where was it freed again?”:

ERROR: AddressSanitizer: attempting double-free ...
    #0 ... in free
    #1 ... in main main.c: second free
...
freed by thread T0 here:
    #0 ... in free
    #1 ... in main main.c: first free

The repair is not automatically “delete the second line”. In a larger program, first decide which code path owns the block. Then make that owner perform one free and make every other path borrow.

The leak appears under Valgrind:

28 bytes in 1 blocks are definitely lost
    at ... realloc
    by ... ints_resize (ints.c:...)
    by ... main (main.c:...)

Seven four-byte ints explain 28 bytes. The allocation stack points to realloc because the resize produced the final live block. Add the missing free to the owner, not to ints_sum or another borrower.
